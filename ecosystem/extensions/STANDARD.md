# Titan Extension Standard

**النسخة:** 0.1
**تاريخ:** 2026-07-28

---

## الفلسفة

Titan يُعلن نقاط التكامل. المجتمع يبني امتداداته فوقها.

هذه الوثيقة تُعرِّف ما هي Extension، وأين تنتمي، وما حدودها مع Titan Core.
كل ما هو خارجها — هيكل الملفات، أسلوب التوثيق، طريقة الاختبارات — قرار صاحب الامتداد.

> إذا أمكن حذف الامتداد من المشروع بحذف سطرَي التهيئة والتسجيل دون الحاجة لتعديل Titan أو تغيير أي Core code، فهو Extension صحيح.
> إذا احتاج إلى تعديل Titan نفسه، فهو Feature Proposal — لا Extension.

---

## ما هي Extension؟

Extension في Titan هو كائن Python يُضيف **قدرة قابلة للتركيب** إلى مشروع Titan
عبر **Public Extension Points** التي يُعلنها Titan — بدون تعديل Core.

Extension لا تنشئ سلوكاً عند الاستيراد. المطور يُهيِّئ، يُسجِّل، يستخدم —
كل خطوة صريحة في كوده.

نقاط التكامل العامة المُعلنة حالياً في Titan:

- `bot.middleware(...)` — نقطة التكامل الأساسية في v1

نقاط التكامل الرسمية مُعلنة في `CONTRACT.md`. مع نمو Titan قد تُضاف نقاط تكامل
جديدة — المعيار يستوعبها بدون تغيير في التعريف.

## الفرق عن Recipe وProject Template

| | Recipe | Extension | Project Template |
|---|---|---|---|
| السؤال الذي يجيب عنه | "كيف أعالج هذا الحدث؟" | "كيف أُضيف هذه القدرة لبوتي؟" | "كيف أبدأ مشروعاً جديداً؟" |
| شكل الاستخدام | `await recipe(ctx)` داخل handler | تهيئة + تسجيل عبر Public Extension Point | نسخ + تملُّك |
| ما يُضيفه | نمط معالجة جاهز | قدرة قابلة للتركيب | هيكل مشروع كامل |
| الحالة الداخلية | لا، أو المطور يمررها | نعم — مُدارة داخل الكائن | لا معنى للسؤال |
| مثال رسمي | `titan.recipes` | `titan.extras` | — |
| اتفاقية التسمية | `titan-recipe-<name>` | `titan-extension-<name>` | `titan-template-<name>` |

الحد الفاصل بين Recipe وExtension هو **نقطة التكامل**:

- **Recipe** تعيش داخل handler — نمط معالجة يُستدعى داخل تدفق موجود.
- **Extension** تتكامل عبر Public Extension Points — قدرة تشارك في دورة المعالجة أو تُضيف طبقة خدمة.

## المرجع الرسمي للنمط

`titan.extras` هو التطبيق الرسمي الأول لنمط Extensions داخل Titan.
`AliasMap` و`AskManager` هما النموذجان المرجعيان لأي Extension تُبنى.

يُظهر هذا النمط ثلاثة عناصر مشتركة في كل Extension ناجح:

**١. التهيئة منفصلة عن التسجيل:**

على سبيل المثال، بالنمط الحالي في `titan.extras`:

```python
# التهيئة — لا شيء يحدث في Titan
manager = SomethingManager(config=...)

# التسجيل — عبر Public Extension Point (أحد الأنماط الحالية)
bot.middleware(manager.as_middleware())
```

**٢. الاستقلالية التامة عن Core:**
Extension لا تعلم بها `bot.py`. يمكن حذفها بحذف سطرَي التهيئة والتسجيل.

**٣. التكامل ثم الاستخدام:**
قد تتكامل Extension مع نقطة التكامل فقط، أو توفر API إضافياً يستدعيه المطور من داخل handlers.
كلا الشكلين صحيح — النمط يتبع طبيعة القدرة التي تُضيفها Extension.

> ملاحظة: الأمثلة في هذه الوثيقة توضيحية وليست حصراً لنقاط التكامل.
> `as_middleware()` هو نمط التنفيذ الذي ظهر في `titan.extras` —
> وليس جزءاً من تعريف Extension نفسها. أي آلية تُحقق التكامل عبر Public Extension Point
> المُعلنة في CONTRACT تُعدّ صحيحة.

## التسمية

الاتفاقية الرسمية الموصى بها:

| | الشكل |
|---|---|
| اسم الحزمة | `titan-extension-<name>` |
| اسم الاستيراد | `titan_extension_<name>` |

من يتبع هذه الاتفاقية تصبح امتداداته قابلة للاكتشاف تلقائياً —
بحث `titan-extension` على PyPI يعطي كل الامتدادات المتاحة.

هذا يخص حزم الامتدادات المجتمعية المستقلة فقط؛ Titan Core نفسها تُثبّت من GitHub.

## التوزيع

Titan لا يفرض وسيلة توزيع. أي وسيلة تسمح بالحصول على الحزمة واستخدامها مقبولة —
مستودع Git قابل للاستنساخ، أرشيف مضغوط، أو غيرها. الاختيار قرار صاحب الامتداد.

PyPI مثال شائع لتوزيع حزمة الامتداد نفسها، لا لتوزيع Titan Core:

```
pip install titan-extension-<name>
```

## الحدود مع Titan

Extension تستخدم فقط ما هو مُعلَن في `CONTRACT.md`.

**Public Extension Points** — نقاط التكامل الرسمية مع Titan:

- نقاط التكامل المُعلنة (راجع `CONTRACT.md` — قسم Public Extension Points)

**Public APIs** — واجهات Titan العامة المتاحة للقراءة والاستخدام:

- أي خاصية أو action في `ctx` — قراءة فقط، لا كتابة دائمة
- `bot.telegram.*`
- النماذج المُصدَّرة: `Sender`، `Chat`، `Message`، `Update`

---

## ما هو ممنوع

هذه حدود معمارية، لا توصيات:

**لا تعديل على Context:**
لا إضافة خصائص أو دوال جديدة بشكل دائم على `ctx` أو أي كلاس في `titan.*`.
أي تعديل per-request زائل (مثل نمط AliasMap) يبقى في نطاق المسموح.

**لا تسجيل تلقائي عند الاستيراد:**
لا شيء يحدث خلف الكواليس. المطور هو من يُسجِّل صراحةً.

**لا وصول للـ internals:**
أي شيء يبدأ بـ `_` في `titan.*` هو implementation detail — Extension لا تعتمد عليه.

**لا monkey-patching:**
لا تعديل على كلاسات Titan أو سلوكها في وقت التشغيل.

**لا حالة خفية:**
إذا كانت Extension تحتاج تخزيناً بين الـ updates، يُمرِّره المطور صراحةً.

## Extensions الرسمية مقابل المجتمعية

| | رسمية | مجتمعية |
|---|---|---|
| مسار الاستيراد | `from titan.extras import X` | `from titan_extension_<name> import X` |
| الصيانة | فريق Titan | صاحب الحزمة |
| الاستقرار | مُجمَّد بعد النشر | semver |

القواعد المعمارية واحدة في الحالتين.

## التوافق مع إصدارات Titan

في `pyproject.toml`:

```toml
[project]
dependencies = [
    "titan-framework @ git+https://github.com/WaheedFox/Titan.git@v1.0.0b1"
]
```

حدّث مرجع الوسم إلى إصدار Titan الذي يستهدفه الامتداد. إذا كانت قناة نشر
الامتداد لا تقبل اعتماديات VCS مباشرة، وثّق تثبيت Titan Core من GitHub
كخطوة منفصلة؛ لا تعتمد على فهرس حزم لتوفير Titan.
